Bringing the shop online

A jewellery catalog customers can browse from home, where every piece shows a realistic all-inclusive price — even though gold and silver rates move every single day. The shop updates the rate once each morning, and the entire catalog re-prices itself.

The problem

A jewellery product has no fixed price

The same payal design gets made at 20g, 23g or 25g depending on what the customer wants. And the metal rate changes daily. Put a price tag in the database and it is wrong within hours.

So the price is never stored. It is calculated, every time, from the weight the customer picks and the rate the shop entered this morning. That one idea is the whole system.

Phase 1 — what gets built first

The shop, browsable

A premium, mobile-first catalog: browse by category, occasion, metal, gender and price. Every product page carries a photo gallery, the weight selector above, a live price, and a WhatsApp button that opens a chat with the piece and weight already filled in.

Behind it, an admin panel deliberately split in two. The daily half is one screen — four rates, one button, thirty seconds — because it is being handed to a non-technical person. Everything else lives elsewhere so that screen stays uncluttered.

There is also a public gold and silver rate page. It is the kind of page people in the district search for by name, and it brings them to the shop's website for free.

What we need

If you are reading this, it is probably one of these

Chartered Accountant
  • Confirm the GST treatment. We apply 3% to the full value — metal plus making charge plus stone — as a composite supply of jewellery. Is that right for this shop, or should making be billed separately?
  • Rounding. Estimates round up, so the displayed figure sits slightly above the invoice. Any issue with that?
  • GSTIN and the invoice format needed from Phase 2.
Photographer
  • One background, one angle, one light across the entire catalog. Consistency matters more than an expensive camera — a phone is fine.
  • Four shots per piece: straight-on, close detail, worn on the body, and one with something for scale.
  • Send originals — not over WhatsApp, which compresses them. No filters: the gold has to be its real colour.
Developer
  • Next.js 16, TypeScript, Postgres 16, Prisma 7. Deployed by Coolify onto an existing Synology NAS, public through a Cloudflare Tunnel already in place.
  • The price engine is a pure function written test-first — no database, no framework, 79 tests across the core. It is the one place a bug shows a customer a wrong number.
  • Metal types are rows, not an enum. A shop adds Silver 925 from the admin panel and the daily rate screen grows an input by itself. No shop fact is hardcoded anywhere, and a test enforces it.
  • Read CLAUDE.md first. It holds the rules that must not be broken — chiefly that price is never stored and the breakdown is never displayed.
